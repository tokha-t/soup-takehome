# Surprise

I expected the production NF4 file to keep most of the FP16 merge’s improvement. By the preregistered relative measure, it did. NF4 retained 98.7% of the matched-precision answer-loss improvement, and Soup returned SHIP for the same weight file. On the 191-row POST-HOC cohort, however, greedy lenient match fell from 70.7% to 60.2%, and valid SQL fell from 95.8% to 86.4%. All 18 validity flips went from valid to invalid. [Official verifier](results/verify_real.json) · [Soup gate](results/ship_b.json) · [POST-HOC headline](results/report_headline_191.json) · [Paired test](results/s5_followup.json)

The export itself was reproducible. Repeating `soup merge --save-format 4bit` produced a byte-identical safetensors file and the same greedy generations. The relative comparison and the SQL validity gate answer different questions about that file. The first measures the improvement preserved by quantization. The second measures how often the shipped decoder returns SQL that SQLite can plan. After repairing the validator, the shipped decoder reached 87.1% valid SQL against the 95% bar.
